组件要摆平的矛盾核心抽象原则在流程里看
引导子系统相互依赖，初始化需遵循先后顺序initcall 级别、1 号与 2 号先建立调度环境，再按依赖初始化，最后把 1 号交给用户态

调度多核公平调度与队列访问的可扩展性每 CPU 运行队列、EEVDF公平在本队列里算；跨 CPU 发生在唤醒和负载均衡时；切换只在安全点

中断设备要快响应，处理又可能很长硬中断 / 软中断 / workqueue硬中断只做必须立刻做的，其余逐级推迟到能睡的上下文
VFS多种文件系统共用同一批系统调用dentry、inode、file名字、对象、打开实例分开缓存；路径查找先走无锁的 RCU-walk
页缓存磁盘慢，进程希望读写像访问内存address_space 里的 folio读写都先碰缓存；回写异步，并用脏页限额卡住写得太快的进程
ext4大文件映射要省，崩溃后元数据要一致extent、jbd2 事务一段区间描述连续块；元数据改动先进日志
块层文件系统懂文件，设备懂队列，两边速度不同bio、request、blk-mq提交是进程里的函数调用；完成是中断，再逐层回调唤醒等待者
终端字符一个个来，程序想要整行；回显要即时flip buffer、n_tty 行规程中断侧只收字符；行规程在 kworker 里回显、攒行，整行才唤醒读者

引导：先能调度，再按依赖点名，最后把 1 号交出去

CPU 复位后从固件入口执行，引导程序负责将压缩镜像装入内存、解压并交给内核。内核按依赖顺序建立内存分配器、VFS、ext4 和 virtio-blk。

所以启动切成两段。start_kernel 在一颗 CPU 上顺序立起内存、中断、时钟、调度和 VFS 缓存，然后 rest_init 拉起 1 号 kernel_init 和 2 号 kthreadd，自己变成 0 号 idle。从这一刻起初始化可以睡眠、可以等磁盘。1 号里 do_initcalls 按级别点名，驱动和文件系统登记自己；console_on_rootfs 在临时根上打开 /dev/console 得到 fd 0/1/2；prepare_namespace 挂上 ext4 根；最后 run_init_process 让同一个 task exec 成 /sbin/init，PID 仍是 1。

进程与调度：可运行的是 task，共享什么由 clone 决定

内核调度和记账的单位是 task_struct，用户态说的“进程”“线程”是它的两种用法。kernel_clone → copy_process 复制 task，clone 标志逐项决定地址空间、文件表、文件系统根、信号、线程组是共享原件还是复制一份。exec 保留 task、换掉 mm；exit 先释放资源变成僵尸，等父进程 wait4 取走退出码才回收。

每颗 CPU 一条运行队列。本版本公平类使用 EEVDF：每个实体有 vruntime 和 deadline（vruntime + slice/权重），pick_eevdf 在有资格（lag ≥ 0）的实体里挑 deadline 最早的。tick 和唤醒通过 TIF_NEED_RESCHED 请求重调度，任务切换在系统调用或中断返回、以及内核允许抢占的安全点执行。

用户看到的clone 上的关键选择内核里的结果
新进程（fork）SIGCHLD新 mm，PTE 共享并写保护，写时复制
新线程CLONE_VM | CLONE_FILES | CLONE_SIGHAND | CLONE_THREAD …同一个 mm，同一个线程组
vforkCLONE_VM | CLONE_VFORK共享 mm，父进程等子进程 exec 或退出

内存：映射是契约，物理页后来补上

用户任务通过 mm_struct 管理地址空间，各段 vm_area_struct 由 maple tree 索引。普通按需映射先建立 VMA，物理页由后续访问触发的 handle_mm_fault 准备：匿名访问使用共享零页或新分配的清零页，文件页从页缓存获取（必要时从磁盘读取），写只读共享页时执行写时复制。

物理内存有两套分配器：伙伴系统按 2 的幂分配连续页，SLUB 在页上切小对象。空闲页低于 low 水位唤醒 kswapd 后台回收，低于 min 时分配者自己直接回收。

文件与页缓存：名字、对象、打开实例分开

路径里的每个分量在 dcache 里找 dentry，dentry 指向 inode，一次 open 得到一个 file（偏移、模式、f_op）。路径查找先在 RCU-walk 下无锁地走，只有遇到需要睡眠的情况（dcache 未命中、要读盘）才退回 ref-walk。

文件数据按 folio 缓存在 inode 的 address_space（一棵 xarray）里。read 先查缓存，未命中才预读；write 只弄脏页缓存里的页，回写线程每 5 秒检查一次，把脏了 30 秒以上的页刷下去。ext4 只在映射逻辑块（extent）和处理元数据（目录、inode、位图，经 jbd2 日志）时出现。

块 I/O：提交是函数调用，完成是中断

bio 描述“这些内存页 ↔ 这些扇区”。submit_bio 在提交者的进程上下文里一路调用下去：blk-mq 尝试和 plug 里的请求合并，分配 tag 得到 request，派发到驱动的 queue_rq。virtio-blk 把请求头、数据页、状态字节三段放进 virtqueue，写通知寄存器后立即返回。提交者若要等结果，就睡在 folio 锁或 buffer 锁上。

本例设备完成后发 MSI-X 中断：vring_interrupt → virtblk_done → blk_mq_end_request → bio_endio → 文件系统的完成回调 → 解锁页、唤醒等待者。硬中断中的完成回调须遵循原子上下文约束；需要睡眠的后续工作交给进程上下文。

输入与终端：字符一个个来，程序要整行

输入分三层：i8042 是 PS/2 控制器驱动，从 0x60 读出字节；atkbd 是键盘协议驱动，把扫描码翻成 KEY_*；输入核心把事件分发给 handler。VT 的 kbd handler 按键盘映射把键码翻成字符，推进 tty1 的 flip buffer。这三层都在硬中断里，到 flip buffer 为止。

flip buffer 的 work 由 kworker 执行，把字符交给行规程 n_tty。规范模式（ICANON）下 n_tty 负责回显（ECHO）、退格和 ^U 这样的行编辑、^C 这样的信号字符，直到收到行结束才更新 canon_head 并唤醒睡在 read 上的进程。输出方向反过来：write → n_tty_write 做 OPOST 转换 → con_write 把字符写进屏幕缓冲，前台 VT 的屏幕缓冲就是 VGA 文本显存。

“打开终端”本身也是一次 VFS 操作：open("/dev/tty1") 经 chrdev_open 换上 tty 的 f_op，tty_open 找到或建立 tty_struct，会话首进程第一次打开时由 tty_open_proc_set_tty 把它设成控制终端。之后键盘上的 ^C 才知道该把 SIGINT 发给哪个前台进程组。

中断、时钟与软中断：逐级推迟

硬中断负责读取设备寄存器、登记后续工作；软中断在 irq_exit 等路径批量执行，两者均须遵循原子上下文约束。workqueue 和内核线程在进程上下文执行，可以睡眠、获取 mutex。积压的软中断转给 ksoftirqd，让用户任务获得运行机会。

时钟是本地 APIC 定时器。高精度模式下周期 tick 只是一个每 CPU 的 hrtimer，CPU 空闲时（NO_HZ_IDLE）可以停掉，直接把 APIC 编程到下一个真正的到期事件。tick 里依次做记账、本地定时器、RCU 静止状态报告和 sched_tick。
