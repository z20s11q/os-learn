# Linux 实时调试学习平台任务卡

设计约束和数据协议以 [总体方案](os-debug-lab-plan.md) 为准。以下脚本名、目录和接口是**任务规格中的产物约定**；实际完成情况见 [验收报告](os-debug-lab-acceptance.md)，执行命令以工作区现有文件为准。一次分配一个子任务；每次先检查前置产物与实际源码。

## 执行顺序和交付约定

```text
T01 环境和 Linux → T02 协议 → T03 调试服务 → T04 实时终端和基础侧栏
                                              ↓
T05 观察扩展 → T06 内存/设备/磁盘 → T07 Linux 对象 → T08 完整联动界面
                                                          ↓
T09 历史回放 → T10 启动与终端课程 → T11 进程/内存课程
                                    → T12 文件课程 → T13 全链路验收
```

T01 包含一次 T05 技术可行性探测，及早验证最难的采集能力。UI 实现可以使用已经采集的真实记录调试渲染；正式联调与验收必须连接实际 QEMU。每项完成时只提交下表规定的任务结果，设计说明引用总体方案：

| 交付项 | 要求 |
|---|---|
| 修改清单 | 文件、职责和必要的接口变化 |
| 复现方式 | 能在当前工作区执行的精确命令，所有变量填入实际值 |
| 验证结果 | 通过/未通过的验收编号、原始证据路径 |
| 真实性 | 实际 QEMU 版本/进程、产物散列、采集来源；尚未提供的字段列为 unavailable |
| 后续依赖 | 下一个任务可直接消费的类型、样例真实帧、已知限制 |

## T01：构建并运行真实 Linux 实验环境

**依赖：** 起始任务。交付范围为环境和真实执行证明。

**允许范围：** `labs/linux-x86_64/`、`labs/profiles/`、`scripts/doctor*`、`scripts/build-lab*`、生成目录。读取已有内核源码，使用独立输出目录；保持现有网页和内核机制。

| 子任务 | 具体工作 | 产物与通过条件 |
|---|---|---|
| T01a 工具和版本 | 检查 QEMU/GDB/工具链/镜像工具，选择实际兼容版本；源码与工具锁定 | `toolchain.lock.json`、`doctor.json`；安装状态以实际检查结果为准，缺失能力逐项记录 |
| T01b 最小 Linux | 按方案配置构建内核、静态 BusyBox、initramfs、ext2 根盘；先用 kernel-fast 验证 | bzImage/vmlinux、内核 .config、BusyBox 符号、rootfs/initramfs；真实 shell 能读写根盘 |
| T01c 观测探测 | 用微型真实指令/内核窗口验证 GDB step、目标描述、物理读、TCG/trace、DMA 和设备字段可用性 | `capabilities.json`，每项有命令和证据；缺失字段形成 T05 的明确清单 |
| T01d 完整启动 | 构建匹配 SeaBIOS 与 GRUB，生成 BIOS 启动盘，配置 linux16/initrd16 | 从复位到 Linux setup、解压、start_kernel、tty1 shell 的真实停点记录；linux16 验证失败时须解决或报告具体阻塞，入口按该协议固定 |
| T01e 用户实验材料 | 根盘添加 hello.txt、确定内容 probe.bin；构建 `lab-read`、`lab-write`、`lab-tty` | 文件散列与源文件可定位；程序只是正常 Linux 应用，能在客体执行 |

**验收：** E01–E03 的命令行证据和 E05 的基础输出。通过条件包括终端 PID、tty、内核版本、镜像散列及实际执行证据。

## T02：冻结协议与持久化格式

**依赖：** T01 的产物清单和实际能力。

**允许范围：** `packages/contracts/`、`packages/trace-format/` 的 schema；只定义协议与持久化格式，调度与内存管理由真实 Linux 执行。

1. 补全总体方案第 7 节所有类型：CPU、内存页、设备、进程、文件、事件、源码和说明引用。
2. 地址/大整数用字符串，字节明确编码与端序；所有对象携带 epoch/frame/capture 归属和证据引用。
3. 除正常数值外，字段必须能表达 `unavailable`、未初始化、未采集和解析中间态。
4. 定义请求幂等、迟到消息、序号缺口、二进制分块、校验散列和能力缺失的错误码。
5. 加入历史模式：`liveFrameId` 与 `viewFrameId` 分离；录制覆盖信息为必填项。

**产物：** `frame.ts`、`command.ts`、`event.ts`、`capabilities.ts`、运行时校验器、录制 manifest schema，以及 T01 实际记录转换来的合法样例。

**验收：** 大地址往返保持精度；缺字段、跨 epoch 数据、错误字节长度被拒绝；真实样例可校验。记录样本仅用于协议测试，运行数据来自实时采集。

## T03：会话、GDB/MI 与 QMP 控制服务

**依赖：** T01–T02。

**允许范围：** `services/lab-server/src/{sessions,adapters,controllers}` 和最小 API。

| 子任务 | 必须实现 |
|---|---|
| T03a 进程管理 | 每会话独立目录和覆盖层；启动 QEMU/GDB、连接 Unix socket；保留 argv 与日志；退出时清理子进程 |
| T03b MI 解析 | token、结果记录、异步 stopped/running、流输出、转义字符串、错误；发现目标寄存器布局 |
| T03c QMP 适配 | greeting/capabilities、命令 ID、异步事件；按实际停止事件关联 QMP STOP 与 GDB 通知并去重 |
| T03d 控制队列 | 单步、源码步入/步过、断点、继续、暂停、停止；命令串行、requestId 幂等、超时后可控停止 |
| T03e 多阶段符号 | SeaBIOS、GRUB、Linux setup、解压器、主内核模块及装载映射；处理同名 startup_64 |

**验收：** E01–E03、E12 的服务层检查。通过 API 连续单步和继续到真实断点；服务返回实际 PC、字节、寄存器及停止原因，日志记录命令结果和采集证据。

## T04：实时终端与 CPU/内存/源码侧栏

**依赖：** T03；这是第一条用户可操作的实时闭环。

**允许范围：** `apps/debugger-web/`，及必要的服务端采集聚合。设备字段只来自实际采集，暂缺字段按 capability 显示。

| 子任务 | 页面行为 |
|---|---|
| T04a 真实终端 | 展示实际串口输出，输入返回串口；绑定正确会话；为后续 VGA/PS2 终端保留独立组件 |
| T04b CPU/代码 | 操作单步、断点和继续；显示普通寄存器、当前模式、原始指令字节、正确模块源码；优化变量显示实际读取结果或原因 |
| T04c 内存 | 地址输入、物理/虚拟空间选择、Hex/ASCII、PC/SP 跳转；显示读取失败和地址空间 |
| T04d 原子更新 | 所有已支持面板从同一个 Frame store 派生；采集中保留上一帧并提示；禁止组件独立轮询 VM |
| T04e 运行模式 | 自由运行终端可用，暂停后完整侧栏更新；清楚标注最后采集时间和当前是否暂停 |

**验收：** 浏览器中启动 Linux、运行 lab-read、在 Linux 函数和用户程序处断点、逐步看到寄存器/内存变化；独立 GDB 对照一致。完成声明限定于实际交付的组件范围。

## T05：可靠的 QEMU 观察扩展

**依赖：** T01c 能力结果、T02 协议；与界面实现分别维护，子任务逐个完成。

**允许范围：** `instrumentation/qemu-observer/`、对应构建脚本与服务适配器；补丁绑定精确 QEMU commit。

| 子任务 | 实现边界 | 必须验证 |
|---|---|---|
| T05a 停止快照 | capabilities、capture/release，CPU 扩展状态、区域表、受控物理 RAM/ROM 读取 | 段缓存/EFER/控制寄存器与独立 dump 一致；MMIO 只从设备快照取值 |
| T05b 事件序列 | 指令尝试、CPU 访存、PIO/MMIO、异常/中断事件；统一序号、drop 计数 | 单步 load/store/in/out 的宽度、地址和值；异常指令按真实异常与停止原因报告 |
| T05c DMA/virtio | virtqueue、设备 DMA read/write、块请求 submit/complete、请求关联 | 客体描述符、实际传输缓冲、LBA 和完成状态对应；CPU 访存与设备 DMA 分别覆盖 |
| T05d 设备快照 | VGA、i8042、UART、PIC/APIC、实际计时器、virtio；只读字段 | 查看面板只读取设备快照，FIFO、IRQ 及 guest 状态保持原值 |
| T05e 屏障并发 | capture 的串行化边界、eventWatermark、pending I/O、后台完成回调 | E09 的实际未完成请求场景，capture 前后事件分类稳定，待完成请求保持其客体状态 |

**验收：** E04、E08–E10。输出每项事件与字段的源代码观察点和锁/线程上下文说明。此任务需要系统代码复核；标准接口已有能力直接复用，QEMU 扩展只补齐缺口。

## T06：内存、页表、设备和磁盘数据服务

**依赖：** T05。

**允许范围：** 服务采集模块、`packages/trace-format`、纯字节解析模块。

1. 按当前运行阶段解析分段和分页；覆盖实际经过的 32 位/64 位页表、大页、未映射/权限错误。
2. 实现可选局部内存采集和完整 RAM 基线/脏页增量；DMA 等路径同样计入变更。
3. 解析 virtio 的实际协商格式及队列内存，保留原始字节引用；能力范围外的 feature 明确拒绝并报告原因。
4. 磁盘以基线和已对客体可见的逻辑完成版本表达，pending 写入独立保存。
5. 全部读取绑定 captureId，历史查询只读对应存档；采集失败时保持最后一个完整帧并报告错误。

**产物：** `memory-reader`、`page-walker`、`virtqueue-decoder`、`disk-version-store`、覆盖统计。

**验收：** E03/E04/E09/E14；停止后的独立 RAM dump 与重建数据相同。关闭 VM 后离线校验根盘，镜像读取须遵守锁约束。

## T07：Linux 对象解析器

**依赖：** T06 与匹配 vmlinux/DWARF。

**允许范围：** `packages/linux-decoder/`；每个解析器只从 `ReadOnlyCapture` 读取同帧证据，GDB/QMP 连接与执行控制由服务管理。

| 子任务 | 起点与输出 | 对照方法 |
|---|---|---|
| T07a 布局 | 从实际 DWARF 生成所需结构 size/offset/枚举，绑定 build ID | 与 GDB `sizeof` 和字段地址对照；内核改变后失效重建 |
| T07b 任务 | init_task 任务列表、per-CPU current、选中 task、state、父子、mm、栈、runqueue 摘要 | 使用匹配的内核 GDB helper/原始内存独立对照；限制遍历深度并检测循环 |
| T07c 地址空间 | 选中 mm/VMA、页表、PFN、权限、选中 folio | 对 Linux 6.12 的 VMA Maple Tree 等实际结构实现限定遍历，使用匹配构建的字段布局 |
| T07d 文件 | task.files → fdtable → file → path/dentry/inode → address_space/folio | 解析 XArray 等实际容器；只展开选定文件；与客体程序报告的 fd/offset 和原始字段比对 |
| T07e 盘面 | ext2 superblock、group、inode、目录项、块映射，文件偏移到 LBA | 用独立 ext2 工具验证关闭后的镜像；缓存和盘面保持两个来源 |
| T07f I/O 关联 | 文件/folio/bio/request/virtqueue/device request 之间的映射 | 保存结构地址、区间、请求 ID 和生命周期；支持合并/拆分、预读和缓存命中；多个候选关联时显示歧义 |
| T07g 用户源码 | mm/exec 世代与用户 ELF 映射，用户栈和 pt_regs | 同一 VA 的不同进程映射正确；BusyBox 静态 ELF 和 lab 程序均能定位 |

**验收：** 用真实 lab-read/fork/memory 程序的停点验证字段。GDB Python 便利函数只在调试器侧读取数据时可使用；对象查询仅通过读取完成。

## T08：完整组件与跨视图联动

**依赖：** T04、T06–T07。

**允许范围：** 前端组件、确定性 selector 和证据详情；只消费实际帧与事件，客体状态由真实执行产生。

| 组件 | 最小交互验收 |
|---|---|
| MachineOverview / CpuPanel | 显示同帧概览，点击寄存器地址跳内存/源码 |
| MemoryPanel / PageTablePanel | 输入 VA 看实际映射、PTE、PA 和字节；标注解析结果与采集范围 |
| BusPanel | 按真实事件播放，区分 CPU、DMA、MMIO、IRQ；点击事件查看 seq 和原始数据；事件太多可聚合但可展开 |
| DevicePanel / VirtqueuePanel | 状态、队列、描述符、输入/输出、IRQ；点击 buffer 跳内存 |
| ProcessPanel | 当前/选中进程、父子、状态、mm、栈、fd；点选只更新观察对象，内核 current 保持原值 |
| FilePanel / DiskPanel | 文件偏移→页缓存→块/请求→磁盘扇区；dirty/pending/完成明确区分 |
| TerminalPanel | VGA/VT 真实显示和 PS/2 键盘输入；另保留串口终端。按键经 QMP 的键盘事件接口或等价受控入口注入，支持 key-down/up，失焦释放按键 |
| ExplanationPanel | 原理、源代码语义、实际字段引用；采集缺口显示 unavailable 与原因 |

**验收：** 同一个 frameId 的所有面板一致；点选对象只执行快照解析。验证 1440×900 布局、代码/Hex 可读性与浏览器脚本错误；真实输入 `cat /data/hello.txt` 后输出一致。

## T09：已执行过程的后退/前进回放

**依赖：** T08 及帧/事件持久化；交付范围为画面数据回放，VM 保持最新停止位置。

1. 区分 `liveFrameId`、`viewFrameId`、实时/回看模式；进入回看先暂停并保存最新帧。
2. 实现后退、前进、拖动时间线、播放速度、返回最新位置；历史模式禁用客体输入和执行控制。
3. 用数据检查点与增量重建画面；CPU、内存、文件、磁盘、外设、终端和解说一起更新。
4. 对未记录指令区间、未记录内存、丢失事件明确显示覆盖范围。
5. 实现录制包导出/导入、散列校验和 schema 版本检查；导入包只作为数据读取，脚本内容保持禁用。

**验收：** E13/E22/E23。随机帧与实时原始采集完全一致；各动画速度下数值相同。回看到过去时 VM 保持最新停止位置，返回最新后还能继续实际运行。

## T13：集成、真实性复核与交付

**依赖：** T01–T12 全部产物。
